1. Project Description (In Simple Words)

❓ What is the problem?

When students or employees feel overwhelmed, sad, or burned out, they often write posts on Twitter, Reddit, or student forums.

  • Traditional tools just look for keywords like "sad" or "depressed" (which causes lots of mistakes).
  • Reading thousands of posts manually is impossible.

💡 What is MindPulse AI?

MindPulse AI is a smart web app that reads a social media post and answers 3 simple questions:

  1. Is the person in emotional distress? (Yes / No)
  2. Why are they distressed? It assigns the reason to one of 6 clear categories:
    • 🏢 Jobs/Career: Heavy workload, boss pressure, exam deadlines, unemployment.
    • 💔 Relationship: Breakups, divorce, romantic grief, family arguments.
    • 🛑 Bias/Abuse: Bullying, cyberbullying, threats, discrimination.
    • 💊 Medication: Adverse side effects from psychiatric pills, dosage changes.
    • 🕳️ Alienation: Chronic loneliness, feeling invisible or disconnected from everyone.
    • ❓ No Reason: Feeling distressed without any clear cause mentioned.
  3. What is the proof? It copies the exact verbatim words from the post as evidence (no hallucinations or speculation).
🛡️ Non-Diagnostic Ethical Rule:
MindPulse AI never provides medical or psychiatric diagnoses. It is strictly a linguistic research tool. If someone is in severe distress, it provides a 1-click button to contact 24/7 emergency crisis hotlines (such as 988).

2.3 Process Descriptions

  • Process 1.0 (Receive & Clean Post): Ingests raw post, validates length (≥ 3 chars), removes malformed input.
  • Process 2.0 (Find Matching Rules): Vectorizes post and retrieves top-3 relevant research guidelines from ChromaDB.
  • Process 3.0 (Run AI Inference): Prompts OpenAI model ($T=0.0$) with retrieved context and post to classify and extract quotes.
  • Process 4.0 (Format & Save Result): Stores analysis in volatile session history and renders structured card on user interface.

Formula:
$$\text{UFP} = 16 + 18 + 15 + 24 + 18 = 91\text{ FP}$$

Step 2: Value Adjustment Factor (VAF)

Evaluated across 14 standard technical characteristics (data communication, usability, performance, etc.). Sum of degrees of influence = 49:

$$\text{VAF} = 0.65 + (0.01 \times 49) = 0.65 + 0.49 = \mathbf{1.14}$$

Step 3: Final Adjusted Function Points (AFP)

$$\text{AFP} = \text{UFP} \times \text{VAF} = 91 \times 1.14 \approx \mathbf{103.74\text{ to }106\text{ FP}}$$
Converting to Code Size (Python ≈ 45 LOC/FP):
$$\text{Code Size} = 104 \times 45 \approx \mathbf{4,680\text{ Lines of Code (4.68 KLOC)}}$$

4. COCOMO Model (Effort, Time, Cost Estimation)

COCOMO (Constructive Cost Model) answers: How long will it take? How many developers do we need? How much will it cost?

Project Mode: Organic

(Small team ≤ 4 developers, familiar problem domain, flexible environment).

  • Size (KLOC): $4.5\text{ KLOC}$ (≈ 4,500 lines of code)
  • Constants: $a = 2.4, \quad b = 1.05, \quad c = 2.5, \quad d = 0.38$
1. Effort ($E$) in Person-Months:
$$\text{Effort} = a \times (\text{KLOC})^b = 2.4 \times (4.5)^{1.05} \approx 2.4 \times 4.85 \approx \mathbf{11.64\text{ Person-Months}}$$ (Meaning 1 developer working alone would need ≈ 11.6 months).

2. Development Time ($D$) in Calendar Months:
$$\text{Time} = c \times (\text{Effort})^d = 2.5 \times (11.64)^{0.38} \approx 2.5 \times 2.54 \approx \mathbf{6.35\text{ Months}}$$
3. Recommended Team Size ($S$):
$$\text{Team Size} = \frac{\text{Effort}}{\text{Time}} = \frac{11.64}{6.35} \approx \mathbf{1.83 \approx 2\text{ Full-Time Developers}}$$
4. Total Development Cost:
Assuming $\$4,000$ (or ₹1,00,000) per person-month:
$$\text{Total Cost} = 11.64 \times \$4,000 \approx \mathbf{\$46,560}$$

6. Agile User Stories (In Simple Format)

Format: "As a [role], I want to [action], so that [benefit]."

Story 1: Single Post Analysis

  • As a: Researcher or evaluator,
  • I want to: Paste a single social media post and click "Analyze",
  • So that: I can see if distress exists, which of the 6 categories caused it, and read the exact evidence quotes.
  • Done When:
    • The predicted category is shown clearly.
    • Verbatim words from the post are highlighted as proof.
  • Points: 5

Story 2: Batch Analysis of Multiple Posts

  • As a: Data scientist,
  • I want to: Paste up to 25 posts separated by blank lines,
  • So that: I can analyze an entire test dataset at once and see an aggregate category percentage bar.
  • Done When:
    • All posts are processed without server crashes.
    • A summary graph shows the category distribution.
  • Points: 8

Story 3: Emergency Helpline Modal

  • As a: User who may be experiencing acute distress,
  • I want to: Click a "Crisis Resources" badge,
  • So that: I can see 24/7 verified crisis phone numbers (like 988) and call them directly.
  • Done When:
    • Clicking the badge opens a popup with verified telephone and SMS helplines.
  • Points: 2

Story 4: Clickable Sample Presets

  • As an: Examiner testing the project,
  • I want to: Click preset buttons (like "Job Burnout" or "Breakup"),
  • So that: I don't have to write my own test posts.
  • Done When:
    • Clicking any chip instantly fills the input text box with a verified benchmark post.
  • Points: 2

Story 5: Export Session History to JSON

  • As a: Student or researcher,
  • I want to: Click "Export JSON",
  • So that: I can download all my analyzed posts and evidence quotes to include in my project submission.
  • Done When:
    • A .json file containing all recent analyses downloads automatically.
  • Points: 3
